Software Requirements Engineering

¿Qué es?

Software Requirements Engineering es el proceso de describir las características y funcionalidades de un sistema de software. Se trata de definir, recopilar y documentar las necesidades del sistema de manera clara y precisa.

Definición de Requisito de Software

Un requisito es una condición y capacidad que debe poseer un sistema de acuerdo a estándares establecidos. Los requisitos pueden ser:

  • Obvios u ocultos: El cliente puede o no expresarlos explícitamente
  • Conocidos o desconocidos: Dependen del análisis inicial
  • Esperados o inesperados: Varían según la perspectiva del cliente

¿Por qué es importante?

Sin una ingeniería de requisitos sólida, los proyectos de software pueden sufrir de:

  • Mala comunicación entre clientes y desarrolladores
  • Productos que no cumplen expectativas
  • Sobrecostos y retrasos en el desarrollo
  • Baja calidad y confiabilidad del software

Temas Principales

1. Elicitación de Requisitos

Proceso de recopilar requisitos de los clientes y stakeholders. Incluye técnicas como:

  • Entrevistas y cuestionarios
  • Observación y análisis de procesos existentes
  • Talleres y sesiones de brainstorming
  • Análisis de documentos y sistemas legados

2. Validación y Verificación

Garantizar que los requisitos sean correctos, completos y consistentes:

  • Revisión con stakeholders
  • Pruebas de consistencia
  • Detección de conflictos y ambigüedades

3. Análisis de Requisitos

Examinar y procesar los requisitos recopilados para:

  • Comprender dependencias y relaciones
  • Diferenciar requisitos funcionales de no funcionales
  • Evaluar feasibilidad técnica y económica

4. Gestión de Requisitos

Mantener y controlar los requisitos a lo largo del ciclo de vida del proyecto, incluyendo cambios y trazabilidad.

Tipos y Modelos

Requisitos Funcionales vs No Funcionales

Funcionales: Describen las acciones que el sistema debe realizar (ej: login, búsqueda)

No Funcionales: Describen atributos de calidad (desempeño, seguridad, escalabilidad)

Modelos de Proceso

El libro cubre diferentes modelos de desarrollo de software:

  • Modelo Cascada: Fases secuenciales y lineales
  • Modelo Iterativo: Desarrollo en ciclos repetitivos
  • Modelo Ágil: Flexible y adaptativo a cambios
  • Modelos híbridos: Combinaciones de los anteriores

Fases Complementarias

  • Diseño del Sistema: Arquitectura y estructura técnica
  • Desarrollo y Configuración: Implementación y control de versiones
  • Aseguramiento de Calidad: Pruebas y validación del producto

Conclusión

La ingeniería de requisitos es fundamental para el éxito de cualquier proyecto de software. Establece las bases para que desarrolladores y clientes compartan una visión común del producto final.
